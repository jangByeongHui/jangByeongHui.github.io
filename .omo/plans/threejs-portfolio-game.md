## Scope
### Must have

- Zero build tooling: plain ES modules loaded via an `<script type="importmap">` pinning `three@0.185.1` and `three/addons/` to the same CDN + version (jsdelivr), per threejs.org/manual/en/installation.html. No `package.json`, no npm, no bundler, no CI/CD workflow.
- New file architecture (all under the repo root / `static/`): `index.html`, `static/css/game.css`, `static/js/content.js`, `static/js/theme.js`, `static/js/scene.js`, `static/js/nodes.js`, `static/js/interactions.js`, `static/js/ui.js`, `static/js/main.js`, `static/media/profile.jpg` (+ a checked-in pastel-circle placeholder image so the site never 404s before the user supplies the real photo).
- Five explorable 3D nodes with real, decision-complete content (see `.omo/drafts/threejs-portfolio-game.md` Decisions section for verbatim copy): About/Personality, Career, Tech Stack, OSS Contributions, Play/Progress (+ completion finale).
- Bright/cheerful pastel visual theme (background gradient + per-cluster pastel node colors), reusing the same font stack as the pre-deletion `index.html` (Black Han Sans, Space Grotesk, Pretendard - see Todo 3 for the exact `<link>` markup, reproduced verbatim since the original file no longer exists on disk).
- OrbitControls-based navigation (drag/touch-drag to orbit, wheel/pinch to zoom) - no WASD/keyboard-only requirement.
- Raycasting hover (cursor feedback + highlight) and click/tap interaction that flies the camera to the target node and opens a DOM info panel populated from `content.js`.
- "N / 5 explored" progress tracker and a light/humorous completion finale (copy authored in `content.js`) plus a `https://github.com/jangByeongHui` link button, triggered once all 5 nodes have been visited.
- Mobile support: touch input parity with mouse, DPR capped at `Math.min(devicePixelRatio, 2)`, and a reduced quality tier (fewer edge segments / no expensive post-processing) on low-end/mobile devices.
- Accessibility/robustness: `prefers-reduced-motion` renders a single static frame instead of an animation loop; a WebGL-capability check falls back to a static HTML summary of the same 5-node content when `WebGLRenderer` construction fails; a `<noscript>` block ships the same 5-node content as plain text for no-JS/screen-reader visitors; the canvas gets appropriate `aria-*` treatment (`aria-hidden` on the decorative canvas, `role="dialog"` + `aria-labelledby` on the info panel).
- `window.__DATA_ORBIT_DEBUG__` (Todo 9) is a QA-only debug global that DOES ship permanently in production and is not gated/removed before launch - it is inert (read-only introspection, no secrets, no privileged app-state mutation), an accepted, documented tradeoff. (Note: the scratch `window.__QA__` used by the Todo 4-8 QA harness is NOT shipped - it is ephemeral, created only by ad hoc `browser_evaluate` calls during QA and never written to any committed file, per the QA harness note above the Todos.)

## Verification strategy
> Zero human intervention - all verification is agent-executed.
- Test decision: **none** (no test framework in this repo, no build tooling by design) - verification is agent-executed **browser QA via Playwright MCP** (navigate, snapshot, click, evaluate JS, read console messages) against a local static server, plus static/manual code inspection for markup and import-map correctness. This is a deliberate repo-appropriate substitute for unit tests, not a corner cut: every todo's QA scenarios below specify the exact Playwright tool call and the exact assertion.

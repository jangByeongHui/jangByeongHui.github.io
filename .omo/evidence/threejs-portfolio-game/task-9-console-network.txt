Annotation (expected 404 exemption):
- `static/media/profile.jpg` does not exist on disk (user-supplied asset, never
  created by any todo — confirmed in Todo 3/5 learnings). Every real page load
  naturally produces this 404 network request from TWO independent code paths
  that both reference `CONTENT.about.photo`:
    1. `static/js/nodes.js`'s `createAboutNode()` — `THREE.TextureLoader().load(...)`
       for the photo Sprite, fired once at `createNodes()` time (main.js boot).
    2. `static/js/ui.js`'s `renderAbout()` — a plain `<img src="./static/media/profile.jpg">`,
       fired only when the `about` info panel is actually opened by clicking the
       About node.
  Both failures are caught by their own `onError`/`error` handlers and fall back
  to `profile-placeholder.svg` without throwing — this is the SAME named,
  documented 404 (not two different unrelated errors) and does NOT count as a
  QA failure per the plan's explicit exemption for `static/media/profile.jpg`.
- Zero OTHER console errors were observed across the full session (5 node
  clicks + finale + no-WebGL failure-path reload).
